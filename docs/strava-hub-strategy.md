# Strava 허브 전략 — 갤럭시 워치 / 애플워치 싱크 경로 조사

> 조사일: 2026-07-09
> 전제: Runners Plan은 Strava API만 연동하고, 삼성/애플 워치 고객은 본인 운동 기록을
> Strava로 싱크하게 안내한다. (자세한 플랫폼별 API 제약은 `api-research.md` 참고)

## 결론

**전략은 실현 가능.** 갤럭시 워치·애플워치 모두 **무료 공식 싱크 경로**가 존재하고,
어떤 경로로 들어온 활동이든 Strava API(`GET /athlete/activities`)에서 일반 활동
(`sport_type: Run`, `distance` 미터)으로 동일하게 조회된다.

단, 두 가지 구조적 함정을 서비스 설계에 반영해야 한다:

1. **과거 데이터 백필 한계** — 삼성 공식 링크는 연동 시점 이후 새 활동만 싱크(과거분 없음),
   애플 공식 가져오기는 과거 30일까지만. → **"가입 직후 지난달 km"는 워치 고객에게 비어 있을 수 있음.**
   온보딩 시 "연동 후 다음 달부터 정확해진다"는 UX로 풀거나, 유료 브릿지 앱(백필 지원)을 안내.
2. **중복 방지** — 고객이 싱크 경로를 2개 이상 켜면 Strava가 중복 제거를 보장하지 않음.
   온보딩에서 "한 가지 경로만" 안내 + 서버측 방어적 중복 제거 필요.

## 1. 애플워치 → Strava

| 경로 | 비용 | 백필 | 비고 |
|---|---|---|---|
| **① Strava 공식 애플헬스 가져오기 (권장)** | 무료 (무료 계정 포함) | 과거 30일 | 애플 기본 운동 앱 기록만 대상 |
| ② Strava watchOS 앱으로 직접 기록 | 무료 | 해당 없음 | Series 4+/watchOS 10+, 폰 없이 GPS 기록 가능(실내 러닝 종목도 지원), 싱크 끼임·배터리 불만 보고 다수 |
| ③ HealthFit (브릿지 앱) | 소액 1회 구매 | 전체 이력 | 데이터 충실도 최고(GPS·심박·케이던스), 백필/서드파티 앱 기록 커버 |

- **① 공식 가져오기**: 2020-02부터 존재(초기 수동), 현재는 "자동 업로드" 토글로 자동 싱크.
  설정: Strava 앱 → 설정 → 앱 관리 → Health → 자동 업로드 허용. GPS 경로는 애플 헬스의
  "운동 경로(Workout Routes)" 읽기 권한을 Strava에 줘야 포함됨. 심박·(사이클) 파워/케이던스도 전달.
  - **애플 기본 운동(Workout) 앱 / Fitness+ 기록만** 가져옴 — Nike Run Club 등 서드파티
    앱이 헬스에 쓴 워크아웃은 명시적으로 제외 (이 경우 HealthFit 등 브릿지 필요).
  - Fitness+ 클래스 연동은 iOS 18.2 / watchOS 11.2 이상 필요 (2025-01 출시). 기본 워크아웃
    가져오기 자체의 최소 OS 요건은 아님.
- 참고: https://support.strava.com/hc/en-us/articles/216917527-Health-App-and-Strava

### 애플워치 고객 안내 문구(안)
> "평소처럼 애플워치 기본 운동 앱으로 달리세요. Strava 앱에서 Health 자동 업로드만
> 켜면 기록이 자동으로 Strava에 쌓입니다."

## 2. 갤럭시 워치 → Strava

| 경로 | 비용 | 백필 | 비고 |
|---|---|---|---|
| **① 삼성헬스 공식 Strava 연동 (권장)** | 무료 | ❌ 없음 | **GPS 활동만** — 트레드밀/실내 러닝 미싱크 |
| ② Health Sync (브릿지 앱) | ~€4 1회 (7일 무료 체험) | ✅ 지원 | 실내 러닝·백필 커버, 공식 링크와 동시 사용 금지(중복) |
| ③ Strava Wear OS 앱으로 직접 기록 | 무료 | 해당 없음 | Watch4+ 전용, 배터리·안정성 불만 보고 있음 |

- **①은 살아있는 공식 기능** (2018년 삼성이 Connected services를 정리할 때 Strava만
  예외로 유지): 삼성헬스 앱 → 설정 → 연결된 서비스 → Strava → OAuth 로그인. 양방향 싱크.
  - **한계**: GPS 기반 활동만 자동 싱크(트레드밀 러닝 제외), 연동 시점 이후 신규 활동만,
    싱크 지연 수분~수시간 보고됨.
  - 참고: https://support.strava.com/en-us/articles/15401747-samsung-health-and-strava
- **주의: Health Connect 경유는 불가.** Strava의 Health Connect 연동은 사실상 쓰기 전용
  (Strava→HC로 내보내기 + 체중만 읽음). 삼성헬스→HC→Strava 가져오기는 동작하지 않음 —
  고객 안내에서 이 경로를 언급하지 말 것.
  - 참고: https://support.strava.com/hc/en-us/articles/43440435267597-Health-Connect-and-Strava

### 갤럭시 워치 고객 안내 문구(안)
> "삼성헬스 앱 → 설정 → 연결된 서비스 → Strava 로그인만 하면 야외 러닝이 자동으로
> Strava에 쌓입니다. 트레드밀에서 주로 달리신다면 Health Sync 앱(1회 구매)을 추천합니다."

## 3. 서비스(서버) 측 설계 반영 사항

1. **월간 km 집계 시 종목 필터**: `sport_type IN (Run, TrailRun, VirtualRun)` —
   트레일런/버추얼런(트레드밀+Zwift류)을 빠뜨리면 과소집계. (`type` 필드는 deprecated,
   `sport_type` 사용.)
2. **방어적 중복 제거**: Strava의 교차 소스 중복 제거는 신뢰 불가. 시작 시각 ±2분 +
   유사 거리 활동은 1건으로 합산하는 로직 권장. `external_id`/`device_name`으로 소스
   추정 가능하나 항상 채워진다는 보장 없음.
3. **싱크 지연 허용**: 삼성 경로는 활동이 수 시간 늦게 도착할 수 있음 — "방금 뛴 기록이
   없어요" CS 대비, 집계는 지연 도착분 재계산 가능하게.
4. **온보딩 타이밍 설계**: 신규 고객의 "지난달 km"는 (a) 기존 Strava 사용자 → 즉시 정확,
   (b) 애플 신규 연동 → 최대 30일 백필로 대체로 커버, (c) 삼성 신규 연동 → 데이터 없음.
   삼성 고객은 첫 달을 "베이스라인 측정 기간"으로 안내하는 UX 권장.
5. **온보딩에서 "한 경로만" 강제**: 예) 기기 선택 → 해당 기기의 권장 경로 1개만 안내.
6. Strava 개발자 측 제약은 그대로 적용됨(개발자 구독, 10명 초과 시 앱 심사,
   `activity:read_all` 스코프, AI/ML 사용 금지 조항) — `api-research.md` 참고.

## 4. 남는 리스크

- Strava가 서드파티 정책을 다시 조일 가능성(2024·2026년에 연속 개정) — 허브 전략 자체가
  Strava 정책에 종속됨.
- 삼성 공식 링크의 "GPS만" 제약으로 트레드밀 위주 고객의 km가 누락됨 — 이 세그먼트가
  크다면 Phase 2(Android 앱 + Health Connect 직접 연동)의 우선순위를 높일 것.
- iOS 18.2 미만 기기 고객은 애플 공식 경로 불가 → 브릿지 앱 안내 필요.
